# V2.8 — Release Readiness

## Objetivo

Consolidar os critérios para considerar a V2.8 pronta para release, sem introduzir alterações funcionais no editor.

## Estado validado

- Quality gates configurados no CI:
  - testes unitários;
  - cobertura V8;
  - typecheck;
  - Biome;
  - build de produção.
- Cobertura mínima configurada:
  - Lines: 80%;
  - Functions: 80%;
  - Branches: 80%;
  - Statements: 80%.
- E2E cobre as jornadas críticas do editor, incluindo acessibilidade, recuperação de erro, PDF, teclado, reduced motion e documentos longos.
- Runner Playwright possui limite de 15 minutos.
- Auditoria inicial de dependências e legado registrada em `docs/09-V2.8-DEPENDENCY-AUDIT.md`.
- Quality gates e evidências registradas em `docs/10-V2.8-QUALITY-GATES.md`.
- PR #95 consolidou a sanitização do stack trace na observabilidade e foi incorporado à `dev`.
- A observabilidade atual mantém logs estruturados e sanitização de dados sensíveis; Sentry/OpenTelemetry não são necessários para concluir esta etapa da V2.8.

## Checklist pré-release

### Código

- [x] Testes unitários existentes passando no último ciclo validado.
- [x] Cobertura com thresholds definidos.
- [x] Typecheck integrado ao CI.
- [x] Biome integrado ao CI.
- [x] Build de produção integrado ao CI.
- [x] E2E das jornadas críticas integrado ao CI.
- [x] Sanitização de mensagens e stack traces de erro.
- [x] Tratamento de reduced motion.
- [x] Fluxos críticos possuem recuperação de erro.

### Dependências e legado

- [x] Dependências diretas auditadas.
- [x] Código legado identificado e documentado.
- [x] Nenhuma remoção especulativa realizada.
- [ ] Remoção de legado pendente de decisão específica e fora do bloqueio da V2.8.

### Produção

- [ ] Executar uma validação final completa da `dev` após o fechamento da documentação.
- [ ] Criar PR de release `dev -> main`.
- [ ] Validar CI/E2E da PR de release.
- [ ] Fazer merge manual em `main`.
- [ ] Validar deployment de produção.
- [ ] Sincronizar `main -> dev` após o release.

## Critério de conclusão da V2.8

A V2.8 poderá ser encerrada quando a validação final da `dev` estiver verde e o release para `main` tiver sido validado em produção.

A existência dos candidatos de legado não bloqueia o release enquanto não houver evidência de uso e risco de remoção.

## Fora de escopo

- Migração para Sentry/OpenTelemetry.
- Alteração do modelo de documento.
- Nova engine de paginação.
- Novos recursos de edição.
- Remoção de arquivos legados sem evidência.
- Atualização ampla de dependências.

Esses itens devem ser tratados em etapas próprias para preservar a estabilidade da V2.8.
